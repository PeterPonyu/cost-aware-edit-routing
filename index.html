Mixed update streams · cost · damage · policy choice

A cost/damage router on mixed edit streams does not beat the frozen majority gate.

The object is a router that, for each item in a mixed update stream, chooses an edit policy from cost and predicted damage. On the frozen mix the router’s edit-majority on the privacy slice is 0.103 against a 0.5 gate. That is a routing measurement, not a shipping claim.

The object

Each stream item can be served by an in-weight edit or by a retrieval arm. The router sees cost (serve GPU time, footprint) and a damage score, then picks an arm.

Integrity of the cell schema is separate from whether the router wins. Provenance can close while the routing rule still loses the majority gate.

What is measured

  • Router edit-majority on the privacy slice: 0.103 (gate 0.5) — does not select edit in the majority of those items
  • Exposure: edit 0.0 vs retrieval 1.0 on the recorded privacy contrast
  • Measured serve-time overhead Δ ≈ 0.100 s (edit 0.020 s, retrieval 0.120 s; n_edit=534, n_rag=304)
  • Footprint Δ on disk is a synthetic contrast in this mix, not a measured allocator

Protocol

  • Build mixed streams with a frozen policy menu.
  • Score each item’s cost and damage features; run the router; record arm choice.
  • Compare edit-majority and cost/damage ablations against the pre-registered gates.

Measurements

Routing outcome

The frozen substantive gate is not met. Majority 0.103 sits well below 0.5. Do not read integrity receipts as a routing win.

What still stands

The measurement schema and 99/99 in-scope provenance cells are internally consistent. They license the numbers above, not a deployed router.
